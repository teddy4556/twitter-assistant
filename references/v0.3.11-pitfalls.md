# v0.3.11 pitfalls — 5 轮失败后的探针版(没修宽度,只加诊断)

## 走了什么路

v0.3.10 用户报告仍不生效, 姐姐承认不知道真因, 加 5 行 console.log 探针 (line 160-168) 收集 4 件事:
- `main` selector 找到几个
- `primaryColumn` 找到几个
- `sidebarColumn` 找到几个
- `header` 找到几个
- `tms-width-style` 标签实际字符数

把 v0.3.10 + 探针 + version → 0.3.11 标识 = v0.3.11。

## 错(姐姐二次错同一类)

**v0.3.10-debug 加探针时只动了 `console.log` 的 v0.3.10 → v0.3.11 字符串, INSTALLED log 标识从 "v0.3.10 ✅ INSTALLED v0.3.10" 改成 "v0.3.11 ✅ INSTALLED v0.3.11"**。

但姐姐**忘了同步 `@version` metadata 字段** — 5 行探针的 v0.3.11 文件 @version 还是 0.3.10。后续 v0.3.11 真正出的时候, @version → 0.3.11 才同步。

**问题**:用户装上 v0.3.10-debug 看到的绿色 INSTALLED log 是 v0.3.10 标识, 不知道装的是 debug 版。如果用户发 v0.3.10 标识的 console 截图回来, 姐姐会以为 v0.3.10 干净版生效, 不知道是 v0.3.10-debug。

**修法**(下个版本必须):探针版的 `@version` + `@name:zh` + 绿色 console.log 标识**必须 3 个同步 bump**, 不能只动 console.log。

## 5 轮失败的总结(从 v0.3.7 到 v0.3.11)

| 版本 | 推论的根因 | 实际结果 | 错在哪 |
|---|---|---|---|
| v0.3.7 | `@run-at document-start` 解决时序 | 输 React inline specificity | 忽略 specificity 优先级 |
| v0.3.8 | inline setProperty + `!important` 解决 | 输 React mount 重置 | 不该用 inline (X 改版后 React 频繁 mount) |
| v0.3.9 | 200ms 轮询找 primaryColumn | 还是 inline 死胡同 | 轮询只解决时序不解决 React 重置 |
| v0.3.10 | 抄 v9.4 简洁架构 | 仍不生效 | "v9.4 能 work"是听说的, 没让用户装 v9.4 验证 |
| v0.3.11 | 加 5 行探针诊断 | **等用户反馈** | 探针标识不同步 bump (本次错) |

**5 轮 4 个不同根因, 4 个错的**。真因仍然未知。SKILL.md status 改 `investigation-paused` 防下次会话盲信。
