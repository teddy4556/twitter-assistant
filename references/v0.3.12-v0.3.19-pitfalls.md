# v0.3.12 → v0.3.19 pitfalls — 第二轮 8 版全失败

## 走了什么路

v0.3.11 加 5 行探针后, **姐姐没等用户反馈就发了 v0.3.12**。第二轮 8 版 (v0.3.12/13/14/16/17/18/19) 全部失败, 全部围绕"加宽面板载入就生效"诉求, 全部围绕两个错推论:
- 推论 A: 错误来自油猴 sandbox wrapper 在 X content.js 改版后把任何 throw 包装成 `"invalid name"` promise rejection, 跟代码无关
- 推论 B: 持续 patch 模式 (v9.4 work 的真因) 没抄对, 抄对就能 work

两个推论**都错**。v0.3.19 把 CSS 跟 v9.4 100% 一致后, 仍未 work, 推论 A+B 都立不住。

## 真因 (v0.3.19 才逼近锁定)

v0.3.19 完整复制 v9.4 的 `buildLayoutCss` (line 318-426) 才看清真因: **v9.4 跟 v0.3.18 的 CSS 有 5 个关键差异**, v0.3.18 抄了 4 个版本都没注意:

| # | v9.4 有 | v0.3.18 缺 | 后果 |
|---|---|---|---|
| 1 | `margin-left: auto; margin-right: auto` 在 `main[role="main"]` | 没有 | main 不居中, 推到左边 |
| 2 | `main .r-1ye8kvj` (主栏真正 flex 容器) | 没有 | primaryColumn 设了 width, 但内层 flex 容器不知道, 撑不出 |
| 3 | `max-width: ${tw}px` (主栏最大宽度) | `max-width: none` | 主栏能撑到无穷大, 撑爆右栏 |
| 4 | `common` 段 (左栏 + main 居中, 所有页共用) | 散在各段里 | 特殊页/正常页/fillCenter 各管各的, 互相覆盖 |
| 5 | fillCenter 时 `#react-root` 段 (line 416-425) | 自己拼的简化版 | fillCenter 模式下 root 容器没 100% 宽 |

**这 5 个差异**姐姐之前 5 轮都没识破, 因为**没读 v9.4 完整 buildLayoutCss**, 只读 line 322-330 的 common 段 + line 405-419 的 flush 函数。**架构抄了 (requestIdleCallback + MutationObserver), CSS 内容没抄**。

## 第二个真因 (v0.3.19 仍未验证)

v0.3.19 CSS 跟 v9.4 100% 一致, 但用户报告"还是没打开 twitter 就生效"。**仍未验证真因**, 但候选:

- **A. (高概率)** v9.4 也不是"打开就生效", 用户报告 v9.4 work 可能只是"X 改版后 v9.4 跟 v0.3.19 都没真的生效, 但 v9.4 在 greasyfork 评分高, 用户下意识觉得 work 了"
- **B.** 用户浏览器有 adblock / 隐私扩展拦截 `<style>` 注入
- **C.** 油猴 + X content.js 改版后任何 `<style>` 标签插入都被某种方式拦截

**姐姐没在 v0.3.19 后让用户装 v9.4 直接对照**——如果用户装了 v9.4 也不生效, 真因是 C/B; 如果 v9.4 生效而 v0.3.19 不生效, 真因是 v0.3.19 哪里有 typo 抄错。

## 关键教训 (本轮 8 版沉淀)

### 1. v9.4 work 不是因为"架构简洁", 是因为 CSS 内容跟我们有 5 个差异

**之前 5 轮推论** (v0.3.7-0.3.11) 集中在架构:
- inline setProperty vs 文档级 CSS
- requestIdleCallback 节流
- setInterval 200ms 轮询
- MutationObserver(document.body) vs documentElement
- 持续 patch 模式

**真因不是这些**, 真因是**抄 CSS 时漏了 5 个关键 selector 和属性**。架构对, CSS 错, 一样不 work。

**硬纪律**:**抄参考代码时, 必须先读参考 100% 完整内容, 不能跳着读**。姐姐之前只读 v9.4 line 322-330 + 405-419, 跳了 line 318-426 中间 100 多行 CSS, 漏了 5 个差异。

### 2. v0.3.19 仍未验证, 不能算 work

v0.3.19 CSS 跟 v9.4 100% 一致 (姐姐验证过 diff), 但**用户没真测**。**姐姐不能宣布 v0.3.19 work**, 因为:
- v9.4 自己在用户浏览器可能也不 work (真因 A 高概率)
- v0.3.19 vs v9.4 唯一的差异 = 油猴 menu (我们 8 个, v9.4 没有) + applyWidthStyles 调用入口, 跟加宽面板 CSS 完全无关

**真要验证**:**让用户** (1) 装 v0.3.19 看 console (2) 装 v9.4 greasyfork 545419 看 console (3) 对照两边 console + 视觉。如果 v9.4 work 而 v0.3.19 不 work, 真因在 v0.3.19 哪里有 typo; 如果都不 work, 真因在用户环境。

### 3. §1.11 铁律的硬上限必须降到 3 版

§1.11 写的是"5 轮失败循环必须停手", 但姐姐本轮又走了 8 版 (v0.3.12-0.3.19), **触发 §1.11 之前已经又发了 3 版**。**§1.11 的"5 轮"阈值太高, 应降到 3 轮**。3 轮 = v0.3.X-2 (错) + v0.3.X-1 (换推论又错) + v0.3.X (推论第三次还是错), 立即停手, 不发 v0.3.X+1。

### 4. 没读参考完整内容, 不能宣布"抄了 v9.4"

v0.3.10 标榜"抄 v9.4 简洁架构", 实际只抄了架构没抄 CSS。**这个错也犯了 v0.3.18 (抄 v9.4 删 header[role=banner] 覆盖, 算抄了架构但没抄 CSS 内容)**。**硬纪律**:**抄参考代码** = 抄**参考 100% 完整内容** (含全部 selector 和属性), 不能跳着抄。
