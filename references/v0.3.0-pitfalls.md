## v0.3.0 改动(2 段)

### 段 6.5:面板宽度读取(在 6 段模板读取后插入)
- 3 个 `WIDTH_KEYS` + 2 个 `WIDTH_LIMITS`
- `getTimelineWidth()` / `getLeftbarWidth()` / `getFillCenter()`
- `WidthStyles.apply` 复用器(仿参考代码 §3)
- `buildWidthCss()` 函数(仿参考代码 §5 buildLayoutCss,简化)
- `applyWidthStyles()` 入口
- `promptInt(key, message, current)` 工具函数(仿参考代码 §9 promptWidth,简化)

### 段 G:菜单 + 启动 + 变更监听(在 F 段后插入)
- G.1 设置时间轴宽度
- G.2 设置左侧栏宽度
- G.3 切换中间填满
- G.4 启动时 `applyWidthStyles()` 一次
- G.5 变更监听:
  - `setInterval(1000)` 监听 path 变化(SPA 内部导航)
  - `MutationObserver` 监听 DOM 变化(新推文加载)
  - 两者都走 `scheduleWidthApply` → `requestIdleCallback` (timeout 300ms)

## 默认值拍板
- `timelineWidth=700`(比 X 默认 600 多 100,推文更宽松但不至于撑太满)
- `leftbarWidth=275`(X 默认值,不动)
- `fillCenter=false`(默认不开,避免宽度变化太突兀)

## 3 个故意不搬的(避免过度工程)
1. ❌ 隐藏左导航菜单(参考代码 §6 hideLeftNavItems)— 你的脚本是"用 X 不改 X",不主动藏
2. ❌ 隐藏"显示更多"(参考代码 §6 toggleShowMoreLinks)— 同上
3. ❌ 图片修复 + 3-4 宫格切换(参考代码 §6 fixPhotoRows)— 不是用户诉求,搬了反而让脚本变 1000+ 行

## 防御设计
- `applyWidthStyles` 是幂等:key 没变 + `<style>` 还在 → 直接 no-op(0 DOM 操作,0 性能开销)
- 特殊页(`/messages` `/settings`)只应用 leftbar 宽度,不动 primaryColumn(避免私讯/设置变形)
- `promptInt` 范围校验:timeline 500-1500,leftbar 200-400,超范围弹 alert 拒绝
- `setInterval(1000)` 监 path 变化 + `MutationObserver` 监 DOM,**两路冗余**(X 改版不破)

## 老用户兼容
- `GM_getValue('tms_timeline_width', 700)` 第二个参数=默认值 → 老用户没存过这个 key,直接用 700
- 老用户没主动改过宽度,体验跟 v0.2.3 一致;改了之后看到新菜单 3 项,可以调
