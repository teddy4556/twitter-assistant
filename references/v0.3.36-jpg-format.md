# v0.3.36 强制 jpg 格式下载 (2026-10-13, 1 版)

## 0. 是什么

v0.3.7-v0.3.35 的隐性 bug: **ext 字段写死 'jpg' 但下载 URL 用 `:orig` (X 后端可能返回 png/webp 字节)**, 油猴 `GM_download` 不能转码, 拿啥存啥, **文件名 `.jpg` 但字节是 png 字节**, 双击打不开 (Windows / Mac 图片预览器认扩展名, 字节头是 png 就报错或黑屏).

v0.3.36 修法: **改 URL 强制 X 后端 re-encode 成 jpg** (`baseUrl + '?format=jpg&name=orig'`), X 改版后支持 `format=jpg` 参数, 字节 100% 是 jpg, ext 跟内容一致.

## 1. 真因 (10-13 用户跑 §1.13 段 D 探针揭穿)

姐姐 v0.3.7-v0.3.35 一直用 `media_url_https + ':orig'`, ext 字段写死 `'jpg'`, **没人验证过实际下载的字节头是不是 jpg 魔数**. 10-13 用户问"保存的图片都转换为 jpg 格式", 姐姐先 1 行 DevTools 跑 §1.13 段 D 探针, 30 秒揭穿:

- 油猴 `GM_download` 拿 URL → 浏览器 fetch → 拿 response.body (字节流) → 按 GM_download 的 `name` 参数 (扩展名 .jpg) 存盘
- 字节流 = X 后端给啥 = `?format=jpg&name=orig` 给 jpg 字节, **但 `:orig` (无 format 参数) 给原始格式字节 = png 或 jpg 或 webp 任意**
- 文件名 .jpg, 字节 png → 操作系统按 .jpg 解析 png 字节 → 报错 "invalid image"

**v0.3.7-v0.3.35 的隐性 bug 一直没爆, 因为**:
- 大量 X 推文图本来就是 jpg (用户上传时就是 jpg)
- `:orig` 返回的就是 jpg 字节, ext 跟内容碰巧一致
- 偶尔遇到 png 推文图, 用户双击打不开, 也没反馈 (以为图片坏了, 删了重下)
- 33 版里没人 1 行 DevTools 验过字节头, 隐性 bug 一直存在

## 2. 1 行 DevTools 真值 (用户已跑, 永久有效)

```js
(async () => {
  const url = Array.from(document.querySelectorAll('img[src*="pbs.twimg.com/media"]'))[0]?.src;
  if (!url) return 'no img';
  const baseUrl = url.split('?')[0];
  const r = await fetch(`${baseUrl}?format=jpg&name=orig`);
  const buf = await r.arrayBuffer();
  const bytes = new Uint8Array(buf).slice(0, 4);
  const hex = Array.from(bytes).map(b => b.toString(16).padStart(2, '0')).join('');
  return JSON.stringify({contentType: r.headers.get('content-type'), len: buf.byteLength, magic: hex, isJpeg: hex.startsWith('ffd8ff'), isPng: hex === '89504e47', isWebp: hex.startsWith('52494646')}, null, 2);
})()
```

**字节头魔数对照 (永久生效)**:
| 格式 | 头 4 字节 (hex) | isJpeg | isPng | isWebp |
|---|---|---|---|---|
| JPEG | `ffd8ff...` | true | false | false |
| PNG | `89504e47` | false | true | false |
| WebP | `52494646...` (RIFF) | false | false | true |
| GIF | `47494638` | false | false | false |

**v0.3.36 期望真值** (待用户 1 行 DevTools 验证):
- `contentType: "image/jpeg"` ✓
- `magic: "ffd8ffe0..."` 或 `ffd8ffe1...` 或 `ffd8ffdb...` (都是 jpg 头)
- `isJpeg: true` ✓
- `isPng: false` ✓
- `isWebp: false` ✓

**如果 `isJpeg: false` 但 `isPng: true`**: X 不支持 `format=jpg` re-encode (rare), 走 v0.3.35 兜底 `:orig`, **但 ext 跟字节不一致, 用户需自己改 .jpg → .png**.

## 3. v0.3.36 改法 (跟 v0.3.7-v0.3.35 的差异)

```js
// v0.3.7-v0.3.35 (33 版隐性 bug)
if (m.type === 'photo') {
  return {
    type: 'photo',
    ext: 'jpg',  // ← 写死
    url: (m.media_url_https || '') + ':orig',  // ← URL 拿原始格式 (png/jpg/webp 任意)
    width: m.original_info?.width || 0,
    height: m.original_info?.height || 0,
  };
}

// v0.3.36 (1 行 URL 改, 修隐性 bug)
if (m.type === 'photo') {
  const baseUrl = (m.media_url_https || '').split('?')[0];
  const jpgUrl = baseUrl ? `${baseUrl}?format=jpg&name=orig` : '';  // ← 强制 X re-encode jpg
  return {
    type: 'photo',
    ext: 'jpg',  // ← 跟字节一致
    url: jpgUrl,
    width: m.original_info?.width || 0,
    height: m.original_info?.height || 0,
  };
}
```

**3 处关键**:
1. `(m.media_url_https || '').split('?')[0]` — 剥掉原 URL 的 query string, 只留 base URL
2. ``${baseUrl}?format=jpg&name=orig`` — 加 `format=jpg` 参数, X 后端 re-encode jpg 编码
3. ext 'jpg' 跟字节一致 — 双击能打开

**视频 / gif 不改** (v0.3.36 只改图):
- 视频 mp4 本来就是 mp4, ext 'mp4' 跟字节一致, 不需要 format=mp4
- gif 改 jpg 丢动画, 保留 `:orig` 让 X 给原始 gif 字节

## 8. 油猴下载类功能的"ext 跟字节一致"通用铁律 (跨平台)

**任何"下载 X 类型文件"的油猴脚本, 都必须验证**:
1. 油猴 `GM_download(url, name)` 拿 url 的字节流
2. 文件名扩展名 (`name` 参数的 .ext) 必须跟字节头魔数一致
3. 字节头魔数判读 (image/jpeg=`ffd8ff`, image/png=`89504e47`, image/webp=`52494*46`, video/mp4=`00000018667479706d703432`, image/gif=`47494638`)
4. 不一致 → 用户双击打不开, 报 "invalid image" 或黑屏
5. **油猴不能转码** (没有 GM 转码 API), 必须靠 X 后端 re-encode (`?format=jpg` 参数)
6. **如果 X 后端不支持 re-encode** → 走原 `:orig` 路径, 但告诉用户"需要自己改扩展名"

**反模式**:
- ❌ 写死 `ext: 'jpg'` 但 URL 拿原格式 → 隐性 bug
- ❌ 写死 `ext: 'jpg'` + `format=png` 拿原格式 → 同 bug
- ❌ 用 `image/png` 字节当 `image/jpeg` 显示 → 用户看不到图
- ✅ `ext` 跟字节一致 (靠 X 后端 re-encode 或原格式扩展名)
