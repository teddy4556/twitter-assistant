# v0.3.7 @run-at document-start 改时机 — 踩坑

## 问题
v0.3.6 4 层 flex 修完后,用户报告"页面**首次**打开时,主栏宽度生效(没问题),但**切回 X 页面**(SPA 切 tab)时,宽度不立即生效 — 等几秒后才跳到目标宽度,有闪烁。

## 根因
v0.3.6 启动用 `@run-at document-idle`(油猴默认),意味着 X 页面已经渲染完了,我们的 CSS 才注入。`WidthStyles.apply()` 在 idle 时调一次 = CSS 标签插入文档时主栏已经是 X 的 600px → CSS 立即覆盖,但**视觉上** X 先用 600px 渲染一帧 → 我们覆盖 → 用户看到 600→700 闪烁。

## 修法(用户拍板 Q1=A)
v0.3.7 改 `@run-at document-start` + CSS 走单独 `<style>` 标签(不进 WidthStyles.apply 缓存):

```js
// @run-at              document-start

// 移入 WidthStyles.apply:document-start 时 head 可能没渲染,fallback 到 documentElement
const el = document.createElement('style');
el.id = id;
(document.head || document.documentElement).appendChild(el);
```

## 上线后**用户仍然报告"宽度不生效"**
- 姐姐以为修好了
- 但用户截图显示**主栏 600px 撑到底**
- console 显示 `[tms v0.3.7] loaded` 装上了

## 真因(被 v0.3.8 诊断)
**v0.3.7 解决了"时序"(CSS 早点注入),但没解决"specificity"**。X 改版后用 React inline style + 多层 hydration 隔离,`!important` 在文档级 `<style>` 标签**输给** inline style。**无论** `@run-at` 多早,CSS 标签永远输给 React 自己 set 的 inline。详见 `v0.3.8-pitfalls.md` 铁律 #5。

## 教训
**@run-at 改时机只解决一半**。X 改版后 specificity 是另一半,必须 inline 双轨。两个问题独立,先后踩到才看清。
