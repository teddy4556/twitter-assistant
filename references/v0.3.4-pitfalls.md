## 4 个真教训(全写到 SKILL.md §1.10,这里给完整版)

### 教训 1:X 改版后 3 栏是 absolute 浮动,**改主栏 width 救不回右栏**

```js
// 错(v0.3.0):只改主栏
main div[data-testid="primaryColumn"] { width: ${tw}px !important; }
// → 右栏被挤出屏,用户截图反馈

// 错(v0.3.1):强钉右栏 width
[data-testid="sidebarColumn"] { width: 290px !important; }
// → 仍然没解决,X 用 transform: translateX 浮动定位,主栏 width 变化不会让右栏让位

// 对(v0.3.2):3 栏全控,所有 width 一起出
header[role="banner"] > div:first-child { width: ${lw}px; }   // 左
main div[data-testid="primaryColumn"] { width: ${tw}px; }     // 主
[data-testid="sidebarColumn"] { width: ${rw}px; }             // 右
```

**WHY**:X.com 改版后 3 栏布局用 `position: absolute` + `transform: translateX(...)` 浮动,不是 flex 流式布局。**改任何一个栏的 width,另两个栏的 `position` 不会自适应**。3 栏必须显式同时控制。

**诊断**:`document.querySelector('[data-testid="sidebarColumn"]').getBoundingClientRect()` 看右栏是否在视窗内,`right >= window.innerWidth` 就被挤出屏了。

### 教训 2:多图轮播接管宽度但别动 aspect-ratio

```js
// 对(v0.3.3 + v0.3.4):只锁 max-width
function buildPhotoGridCss() {
  return `article [data-testid="ScrollSnap-List"] { max-width: 100% !important; }`;
}
// → 图片不裁切,X 原生 aspect-ratio / padding-bottom 算高度

// 错(没做,但差点做):接管 height 或加 grid-template-columns
// → 图片被裁成方块,富媒体体验差
```

**WHY**:X 改版后多图轮播容器是 `article [data-testid="ScrollSnap-List"]`,内部用 `position: relative; padding-bottom: N%`(按图片比例 16:9 / 4:5 / 1:1)算高度,图片用 `object-fit: cover` 填充。脚本接管 height → 图片裁切;接管 `aspect-ratio` → 比例错乱。**只动 width,让 X 自己算 height**。

**真要切栅格**(单/2/3+ 张图切不同布局)→ 搬参考代码 Clean-up v9.4 §6 `PHOTO_GRID_BASE_CSS` 完整版(150+ 行,带 aspect-ratio 智能分支),**别自己拍脑袋**。

### 教训 3:`display: none` 影响范围比想象大,藏前先验证

```js
// 错(v0.3.3 姐姐自作聪明加的):
article [data-testid="ScrollSnap-prevButtonWrapper"],
article [data-testid="ScrollSnap-nextButtonWrapper"] { display: none !important; }
// → 3+ 张图无法用按钮翻页,只能用滚轮/手势,桌面端体验降级
// → 用户截图反馈,v0.3.4 撤回

// 隐藏前必做(浏览器 dev tools 模拟):
// 1. 藏后用户怎么完成"原本能完成"的操作?
// 2. console 跑 querySelector 检查是否影响其他 selector
// 3. 真要藏,配套加替代交互(滚轮监听 / 键盘快捷键),别只藏不补
```

**WHY**:X 改版后 DOM 结构反直觉,看着"装饰"的元素(`ScrollSnap-prevButtonWrapper` / `ScrollSnap-nextButtonWrapper` / 各种 sticky 浮窗 / 折叠按钮)其实都是用户主要交互入口。**先验证再藏,藏了要补**。

### 教训 4:用户拍板删功能时一次性彻底删

v0.3.4 删阅读位置功能,姐姐一次删干净:
- D 段 `getArticleTweetId/Author/Timestamp` + `getTopVisiblePost` + `saveReadingPosition` + `scheduleReadingSave` + `applyHighlight` + `findArticleByBookmark` + `jumpToReading`(84 行)
- E 段 油猴菜单 `✅/⏹️ 自动跳转` 开关 + `__tmsClearReading` 隐藏函数(15 行)
- F 段 启动时 `jumpToReading` 触发逻辑(10 行)
- 2 个 GM_key(`tms_reading_position` / `tms_reading_auto_jump` —— 老用户旧值还在,占 ~50 字节,删不删不影响功能)
- 1 个 CSS class `tms-reading-highlight`(4 行)
- loaded log 去掉"自动跳转" + "已记住"字段(2 行)

**总删除 196 行**,一次到位,不留僵尸代码或半成品。

**反例(姐姐差点做)**:只删菜单项,保留 D 段工具函数,等下次"重构"时再清 → 结果是 196 行死代码长期占空间,任何引用都报 undefined。

**派生铁律**:用户拍板 X → 当次 commit 内**全删干净** → 下次会话看不到,新人接手也看不到,**不留技术债**。

## 关键代码:buildWidthCss + buildPhotoGridCss

```js
function buildWidthCss() {
  const tw = getTimelineWidth(), lw = getLeftbarWidth(), rw = getRightbarWidth();
  const fc = getFillCenter(), hl = getHideLeftbar(), hr = getHideRightbar();
  if (/^\/(messages|settings)/.test(location.pathname)) {
    return `${hl ? 'header[role="banner"] { display: none !important; }' : `header[role="banner"] > div:first-child { width: ${lw}px !important; }`}`;
  }
  if (fc) { /* fillCenter 分支:主栏 100% + 右栏固定 + 多图接管 */ }
  return `/* 非 fillCenter 分支:3 栏固定 + 多图接管 */`;
}
function buildPhotoGridCss() {
  return `article [data-testid="ScrollSnap-List"] { max-width: 100% !important; }`;
}
```

**两个分支都加 `${buildPhotoGridCss()}`** —— fillCenter + 非 fillCenter 都同步接管多图。
