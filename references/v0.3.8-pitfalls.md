# v0.3.8 加宽面板 inline style 双轨 — 踩坑

## 问题
v0.3.7 改 `@run-at document-start` + CSS 走单独 `<style>` 标签后,**首次打开页面 / 切回 X 页面,主栏宽度仍然不生效**(截图:主栏 600px 撑爆右栏)。

## 根因(超出预期)
**不是时序问题**。X 改版后用了**多层 style 作用域隔离**:

1. 文档级 `<style id="tms-width-style">` 注入到 `document.documentElement`(`<head>` 没渲染时 fallback)
2. X 自己的样式通过 React 组件 **inline style** + 多层 `__NEXT_DATA__` hydration 注入
3. **`!important` 在文档级 `<style>` 输给 inline style**(inline style 总是赢,除非用 `!important` 加更高 specificity)

**v0.3.6 → v0.3.7 改 @run-at document-start** 解决了时序(姐姐的 CSS 早点注入),**没解决 specificity**。

## 修法(用户拍板 Q1=C)
直接走 `element.style.setProperty('width', '700px', 'important')` 写 inline,完全绕开 specificity 问题。

### 双轨设计
```
启动时:
  1. 注入 <style> CSS(照常,v0.3.7 不动,兜底用)
  2. 立即调 applyInlineWidths() 写 inline 覆盖
  3. MutationObserver 监听 primaryColumn 节点,出现就 setProperty 覆盖
```

**关键点**:
- `setProperty('width', '700px', 'important')` 走 `cssPriority=important`,在 inline style 里**强过任何外部 `<style>`**(包括 X 自己)
- CSS 注入照常(v0.3.7 不动),inline 被 X React diff 重置时 CSS 救场
- 节流:1 次 / 50ms,避免 SPA 频繁切 tab 时重复 setProperty 抖性能

### applyInlineWidths 覆盖节点(5 个)
1. **主栏** `main div[data-testid="primaryColumn"]` → `width: 700px` + `max-width: 700px`
2. **内部 flex 容器** `main div.r-1awozwy.r-18u37iz` → `width: 100%` + `display: flex` + `flex-direction: row`
3. **内容容器** `main div.r-16y2uox` → `flex-grow: 1` + `width: 100%` + `min-width: 0`
4. **左栏** `header[role="banner"] > div:first-child` → `width: 275px` 三件套
5. **右栏** `[data-testid="sidebarColumn"]` → `width: 290px` 三件套
6. **main 容器**(`fillCenter=true`)→ `width: 100%` + `max-width: none`

## 特殊页判断
```js
const isSpecial = /^\/(messages|settings)/.test(location.pathname);
```
私讯 / 设置页**不应用时间轴宽度**(避免变形),跟 v0.3.6 的 buildWidthCss 逻辑一致。

## 调用点(全部双轨,inline + CSS 一起)
- G.4 启动时:`applyWidthStyles() + applyInlineWidths()` 同步执行
- G.5 路径变化:`scheduleWidthApply()` 内部 `applyWidthStyles() + applyInlineWidths()` 一起调
- G.5 DOM 变化(`MutationObserver`):同上
- 油猴菜单所有 5 个宽度菜单:全部 `applyWidthStyles() + applyInlineWidths()` 双调

## v0.3.7 → v0.3.8 文件变化
- **+95 行**:`_applyInlineWidthsNow` 函数(~50 行) + `applyInlineWidths` 节流函数(~10 行) + 注释 + 9 处调用点 + 11 处 log tag 升版
- **0 行删除**:v0.3.7 的 CSS 注入保留做兜底
- **0 selector 改动**:`buildWidthCss` 不动,只是加了 inline 这一轨

## 实测验证步骤(用户)
1. 油猴 → Twitter 助手 → 替换 v0.3.7 为 v0.3.8
2. **首次装**:console 看到 `[tms v0.3.8] loaded ... | 面板宽度: 时间轴=700px ...`
3. 切到别的 tab → 切回 /home → 主栏立刻 700px 宽(无 600→700 闪烁)
4. 改宽度(油猴菜单 → 设置时间轴宽度 → 800):主栏立刻 800px
5. F12 选中 `main div[data-testid="primaryColumn"]` → Styles 标签看到 `width: 800px !important;` 在 inline style 块里

## 关键教训
**X 改版后,任何想改 X 样式的脚本,都不能只靠文档级 `<style>`**。要么 inline 强制(本方案),要么走 Shadow DOM 内部(更复杂)。inline 一定赢是浏览器铁律,specificity 无法越级。
