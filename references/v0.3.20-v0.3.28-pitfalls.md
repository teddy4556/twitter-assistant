# v0.3.20 → v0.3.28 加宽面板 9 版失败循环 (2026-10-13)

**核心教训**: v0.3.6-0.3.19 抄 v9.4 不完整 → v0.3.20-0.3.27 跟 v9.4 100% 一致 → 但 9 版**全部失败**, 真因 = **同时装 v9.4 + v0.3.x 测, v9.4 赢 specificity 覆盖 v0.3.x**。用户卸 v9.4 单测 v0.3.27 后立刻 work, 25+27=52 版的真因就这么简单, 但 52 版才发现。

## 52 版 (含 v0.3.0-v0.3.19) 累积真因

| 真因 | 错了几版 | 何时识破 |
|---|---|---|
| 1. CSS 不完整 (跟 v9.4 缺 5 个属性) | v0.3.6-0.3.18 = 13 版 | v0.3.19 完整抄 v9.4 后 |
| 2. 架构太花哨 (持续循环/探针/try-catch/延迟) | v0.3.6-0.3.18 = 13 版 | v0.3.25 砍光后 |
| 3. 命名/cache key 跟 v9.4 不一致 | v0.3.6-0.3.26 = 21 版 | v0.3.26 cache key 跟 v9.4 一致后 |
| 4. **同时装 v9.4 测, v9.4 specificity 永远赢** | v0.3.6-0.3.27 = 22 版 | v0.3.27 用户卸 v9.4 单测后 |
| 5. Styles.apply cache 命中跳过 + React 重渲染覆盖 | v0.3.27 = 1 版 | v0.3.28 启动 0/100/500ms 强制重写 3 次修 |

**52 版踩 5 个真因, 真因 1-3 在 v0.3.6-0.3.18 修过 21 版, 真因 4 在 v0.3.6-0.3.27 让用户装 v9.4 测 22 版 (姐姐从没让用户"卸 v9.4 单测"), 真因 5 在 v0.3.27 修 1 版**。**5 个真因中, 真因 4 (同时装 v9.4 测) 占 22 版 — 是单一最大失职**。

## 用户 4 个新硬偏好 (本会话新沉淀)

1. **第一时间让用户跑 DevTools 4 行真值**: `document.querySelector` + `getComputedStyle().width` + class + 嵌套关系, 不要反复改 CSS / selector / patch 周期猜
2. **不要让用户同时装多个版本测** (尤其 1 个 work 的 + 1 个 不 work 的), 永远要求"卸 X 单独测 Y"
3. **公开代码 work 的真因 = 跟 X 改版正交 (靠 specificity + !important 拼, 不依赖 X 内部具体 class)**, 不是它写得多好
4. **用户原参考 work 的脚本, 抄的"全部" = 它 work 的全部, 不要加你以为更好的东西** (v0.3.6-0.3.24 加的 inline 双轨 / 持续循环 / 探针 / try-catch / 启动延迟 = "花里胡哨", v0.3.25 砍光后跟 v9.4 一致才 work)
