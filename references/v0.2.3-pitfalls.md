# v0.2.3 闭环 — 阅读位置自动跳转功能放弃

## 用户拍板
v0.2.2 跑通 29.5s 重试 + selector 兜宽 + 失败诊断后,实测场景:
- savedReading = @SilkySuki_/2105912604552274237 (savedAt 2026-10-13 02:24)
- 13 天前的推文,刷新 /home 后 article 数=6,含目标 id? **false**
- 用户手动访问 `x.com/SilkySuki_/status/2105912604552274237` → 推文还在(假设 B 排除)

**真因**:`/home` 算法流只展示近期 50 条左右,13 天前的推文早被挤出首屏,5-7 次 29.5s 重试无论怎么等都不会出现。

## 4 个修法评估(用户拍板第 4)
1. ❌ 加更多重试(10+ 次 60s+):/home 流的深度上限就是 1-3 天,13 天前永远找不到
2. ❌ 模拟用户向下滚找目标:同上,流深度不够,而且会污染用户当前位置
3. ❌ 跳到推文详情页:用户拍板"留在 /home",跳走违反诉求
4. ✅ **关掉这个功能**(用户拍板):autoJumpEnabled 默认 false,菜单开关保留,以后想开可手动开

## v0.2.3 改动(3 处)
1. `autoJumpEnabled` 默认 `true` → `false`(`GM_getValue` 第二参)
2. 启动判断逻辑恢复 v0.2.0 简洁版(去掉 v0.2.3 中间过渡的 3 场景分支,只保留 1 个 if)
3. 12 处 log tag `[tms v0.2.2]` → `[tms v0.2.3]`,`@version 0.2.2` → `0.2.3`
4. 油猴菜单标签反映关闭态:第一次装的人看到 `⏹️ 自动跳转到上次阅读位置 (关闭 · 点击开启)`

## 老用户兼容
- `GM_getValue(AUTO_JUMP_KEY, false)` → 老用户 GM_setValue 里已存了 true,继续用 true(不受默认 false 影响)
- 只有全新装 v0.2.3 的人 + 从没点过菜单的人,默认是 false
- 真要关:菜单点一下,GM_setValue 写 false,刷新就生效

## 5 个版本迭代教训(本会话沉淀)
1. v0.2.0 → v0.2.1:加 `autoJumpEnabled` 开关,user 拍板"不要手动跳转"
2. v0.2.1 → v0.2.1.1:加诊断 log,但**用户没装**(console 没 v0.2.1.1 字样),所以下版本前的诊断全靠猜
3. v0.2.1.1 → v0.2.2:拉长重试节奏到 29.5s,放宽 selector 兜底,加失败诊断
4. v0.2.2 → v0.2.3(中):改跳推文详情页(未发布,因为 user 拍板"别跳")
5. v0.2.3(终):关掉功能,**承认** X.com /home 算法流装不下老推文,自动跳在此场景下是空跳

## 沉淀的 2 个铁律
- **产品逻辑铁律**:X.com /home 时间线**只装得下 1-3 天内的推文**,任何"基于 tweetId 自动跳"的方案都不可能覆盖全部用户场景。要么接受"只在够新时跳",要么放弃这个功能。v0.2.3 选了后者。
- **诊断铁律**:用户装 v0.2.1.1 后 console **根本没出现 v0.2.1.1 字样**,说明 4 个版本用户都没装(被 TM 缓存或没刷新)。下次加诊断时,顺便在 `console.log` 第 1 行打 `tms v0.2.X loaded`,这样用户看一眼就知道装没装上。

## 不再追的方向
- v0.2.4 不会做"滚找"(产品上不灵,X 改版也让滚找逻辑不稳定)
- v0.2.4 不会做"跳详情页"(用户拍板"留在 /home")
- 如果用户真要自动跳,改用 X.com 自带的"Bookmarks"功能,这是 X 自己设计的"自动跳到上次书签"产品
