## 2. v0.3.33 UI 增强

v0.3.32 slider 拖动时数字实时变, 但眼睛可能跟不上. v0.3.33 改 3 处:

### 2.1 slider ↔ number input 双向同步

```js
['tms-tw', 'tms-lw', 'tms-rw'].forEach(id => {
  const slider = document.getElementById(id);
  const num = document.getElementById(id + '-num');
  // slider 拖动 → 同步 number input
  slider.oninput = () => { num.value = slider.value; };
  // number input 输入 → 同步 slider (验证 min/max)
  num.oninput = () => {
    const v = parseInt(num.value, 10);
    const min = parseInt(slider.min, 10);
    const max = parseInt(slider.max, 10);
    if (!isNaN(v) && v >= min && v <= max) slider.value = v;
  };
  // number input blur → 强制修正 (超出范围改回 min/max)
  num.onblur = () => {
    let v = parseInt(num.value, 10);
    if (isNaN(v)) v = parseInt(slider.value, 10);
    else if (v < min) v = min;
    else if (v > max) v = max;
    num.value = v;
    slider.value = v;
  };
});
```

### 2.2 +/- 10px 步进按钮

```js
document.querySelectorAll('.tms-minus, .tms-plus').forEach(btn => {
  btn.onclick = () => {
    const targetId = btn.dataset.target;
    const step = parseInt(btn.dataset.step, 10);
    const slider = document.getElementById(targetId);
    const num = document.getElementById(targetId + '-num');
    let v = parseInt(slider.value, 10) + step;
    if (v < parseInt(slider.min, 10)) v = parseInt(slider.min, 10);
    if (v > parseInt(slider.max, 10)) v = parseInt(slider.max, 10);
    slider.value = v;
    num.value = v;
  };
});
```

### 2.3 应用按钮读 number input 优先 (用户直接输的数优先)

```js

  const tw = parseInt(document.getElementById('tms-tw-num').value, 10);
  // ...
  GM_setValue(WIDTH_KEYS.timeline, tw);
  // ...
  applyWidthStyles();
  panel.remove();
};
```

## 4. 31 版总教训 (永久生效, 写 SKILL.md §1.12 同步)

### 4.1 油猴 sandbox "invalid name" throw 铁律

- **callback 闭包绝不能引用 page script 函数** → 改用自创 HTML 面板
- **真因查询用 `id^="tm-"` 不用 `id^="tms-"`** (v9.4 同款 ID, 永远能查到)
- **第一次失败立即让用户跑 1 行 DevTools** (4 值 30 秒定位)
- **"花里胡哨"全砍** (inline 双轨 / 持续循环 / 探针 / try-catch / 启动延迟)
- **抄 v9.4 必须 100% 完整 + 用同款 style ID**
- **加宽面板用悬浮按钮 + 自创 HTML 面板, 不用 5+ 个油猴菜单**

### 4.2 姐姐 31 版的认知错 (永久生效)

1. **28 版没让用户跑 DevTools** — 用户今天 1 行 `style: 0` 揭穿 28 版全错
2. **28 版分析 "v0.3.x 跟 v9.4 拼 specificity"** — 完全错, v0.3.x 一直 work
3. **28 版分析 "v0.3.x CSS 不 work"** — 完全错, CSS 一直 work, 是姐姐查询错 (`id^="tms-"` 永远 0)
4. **8 月底沉淀的 inline 双轨铁律** — 28 版没用, 真正该沉淀的是 "callback 闭包引用 page script 函数 throw"
5. **姐姐不知道 X 改版会验证 page script 函数引用** — 31 版才学到的真相

### 4.3 v9.4 在用户浏览器 work 的真因 (v0.3.32 验证)

- v9.4 没设任何加宽菜单, **没有 callback 闭包引用 page script 函数**, 油猴 wrapper 不验证 → 不 throw
- v9.4 的 CSS (4 个关键 selector + 文档级 style + !important) 跟 v9.4 0 菜单组合 = 完美稳
- 之前 28 版姐姐分析 "v0.3.x 跟 v9.4 拼 specificity" **完全错** — 实际是 v9.4 0 菜单从来不 throw
