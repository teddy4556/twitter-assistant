# v0.3.10 pitfalls — 回归 v9.4 简洁架构

## 走了什么路

v0.3.9 失败后, 用户贴了 v9.4 greasyfork 388 行参考 (X/Twitter Clean-up & Wide Layout Display v9.4, Hzbrrbmin)。姐姐读 v9.4 源码, 提取架构:
- `@run-at` 不写(油猴默认 = document-end)
- `new MutationObserver(onMutations).observe(document.body, { childList: true, subtree: true })`
- `cleanUpAndResize()` 立刻跑一次
- `onMutations` 收 addedNodes 到 `pending` set
- `requestIdleCallback(150ms)` 节流, 浏览器闲时才处理
- 文档级 `<style>` + `!important`

**结论**:v0.3.10 删了 v0.3.8 的 inline setProperty (91 行) + v0.3.9 的 200ms 轮询 (22 行), 走 v9.4 简洁架构。

## 推论的根因(错的)

"inline 方案不稳, React mount 重置 inline style, 文档级 CSS + !important 一定能赢" — 油猴社区广泛传播的"事实", 姐姐当时未验证就信了。

立成 fact #521 写进 SOUL, 推论成 5 段铁律第 5 条。

## 实际结果

v0.3.10 = v9.4 架构 95% 相同 (buildWidthCss 都有 `main[role="main"]` + 4 层 flex + 6 个 r-* class)。

用户报告 v0.3.10 仍不生效, console 显示 `applyWidthStyles` 跑到了, `buildWidthCss` 跑到了, **但页面宽度没变**。

## 不工作

姐姐没意识到"v9.4 在用户浏览器可能也不工作" — 5 轮都基于"v9.4 能工作"推论, 但**从来没让用户装 v9.4 验证**。

## 复盘

**v0.3.10 的 CSS 内容跟 v9.4 几乎一样, 架构跟 v9.4 几乎一样** — 但**用户浏览器装了 v9.4 也不一定生效**。姐姐犯的核心错:把"参考存在 = 参考有效"当推论, 没在用户环境验证过参考本身。

## 修法

1. 停止推论"v9.4 简洁架构必然 work"
2. 让用户**先装 v9.4 greasyfork 545419 直接装**对照
3. v9.4 装上若生效 → 真因在 v0.3.10 实现差异 (但实际差异只有 1-2 行)
4. v9.4 装上若也不生效 → 真因在用户环境 (扩展 / 浏览器), 油猴脚本救不了

## 跟其他版本的关系

v0.3.7 失败 → v0.3.8 inline 双轨 → v0.3.9 轮询 → v0.3.10 抄 v9.4 → v0.3.11 加 5 行探针。**5 轮 4 个不同推论, 4 个错的, 1 个不知道**。
